# Expense Management API

FastAPI + MariaDB backend for a single-company expense approval platform.
**Status: skeleton.** Routes, schemas, models, services and permissions are all defined and documented;
the business logic is intentionally not written yet (stubs raise `501` / `NotImplementedError`).

## Run it

```bash
# 1. Database (MariaDB in Docker)
docker compose up -d db

# 2. Python environment
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# 3. Configuration
cp .env.example .env            # then edit values (JWT secret, Resend key...)

# 4. Create tables (first time: generate the initial migration, then apply it)
alembic revision --autogenerate -m "initial schema"
alembic upgrade head

# 5. Seed admin user, default categories, settings  (needs the services implemented)
python -m app.seed

# 6. Start the API
uvicorn app.main:app --reload
```

Open **http://localhost:8000/docs** (Swagger UI) or **/redoc**. Every route, its required
permission, and every request/response object is documented there.

## Project layout

```
app/
  main.py              app creation, router registration, OpenAPI metadata
  seed.py              initial data (admin, categories, settings)
  core/
    constants.py       ALL fixed values: enums, state machine, limits, defaults, messages
    config.py          environment settings (.env)
    database.py        engine + session dependency
    security.py        password hashing, JWT, get_current_user
    permissions.py     route permission declaration + registry (RBAC core)
    deps.py            short dependency aliases (DbSession, CurrentUser, Pagination)
    exceptions.py      shared error types
  models/              SQLAlchemy tables, one file per table
  schemas/             Pydantic request/response shapes, one file per resource
  services/            business logic, one file per concern
  routes/              HTTP endpoints, one file per resource
alembic/               migrations
```

## Key ideas

**Workflow.** `pending_manager` -> `pending_finance` -> `approved`; `rejected` / `needs_changes` branch off.
The transition table is in `core/constants.py`; only `ExpenseWorkflowService` may change a status.

**Permissions.** Each route declares its permission inline with `**protected("name", "description")`.
Declared permissions are collected in a registry, synced into the `permissions` table at startup
(ids generated by the database) and listed by `GET /permissions`. Users get permissions from
groups plus optional direct grants. The `admin` superuser (`is_superuser=True`) bypasses permission
checks in exactly one place (the dependency built by `protected`); there are no separate admin routes.

**Visibility.** `GET /expenses` returns own / department / all expenses depending on the highest of
`expenses.view_own`, `expenses.view_department`, `expenses.view_all` the caller holds.

**Services vs routes.** Routes declare the contract and delegate; services hold logic, own commits,
and raise errors from `core/exceptions.py`.

**Notifications.** Email only (Resend), sent as background tasks, nothing stored in the database.

**AI.** Not in the MVP routes. `services/ai_client.py` defines the interface your model will plug into,
and `Expense.ai_analysis` is reserved to store its output.

## Adding a new endpoint

1. Add request/response models in `schemas/`.
2. Put the logic in a service method (signature + docstring first).
3. Add the route in `routes/` with `**protected("resource.action", "What it allows", details="...")`.
4. Restart: the new permission appears in `GET /permissions` and can be assigned to groups.

## Where to start implementing

`security.py` -> `permissions.py` checker -> `permission_sync.py` -> `seed.py` -> `auth_service.py`
-> `user_service.py` / `rbac_service.py` -> the rest. Once login and permission checks work, every route
can be built and tested through `/docs`.
